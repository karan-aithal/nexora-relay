# Phase 1 — ISO 8583 Codec and Acquiring Host Simulator

**Goal:** A correct, well-tested ISO 8583 message codec and a TCP host simulator that
authorises, declines, times out and handles reversals.

**Read first:** `CLAUDE.md`, especially section 11 on not inventing spec details.

This is the highest-value phase in the project. Almost nobody outside payments has
written a bitmap parser. Spend the effort here.

## In scope
- `OpenForecourt.Iso8583` — encode/decode
- `OpenForecourt.HostSimulator` — async TCP acquirer

## Deliverables

### Codec
- **Data-driven field definitions.** A field table describing each field's type
  (fixed / LLVAR / LLLVAR), length, and encoding (ASCII numeric, binary, alphanumeric).
  No hard-coded per-field parsing logic. Document that real acquirers use proprietary
  dialects and that this project defines its own documented variant based on the
  ISO 8583:1987 field set.
- Primary and secondary bitmaps, 8 bytes each, bit 1 signalling the secondary
- Fixed, LLVAR and LLLVAR handling with length-prefix encoding
- Fields at minimum: 2 (PAN), 3 (processing code), 4 (amount), 7 (transmission
  datetime), 11 (STAN), 12/13 (local time/date), 22 (POS entry mode), 37 (RRN),
  38 (auth code), 39 (response code), 41 (terminal id), 42 (merchant id),
  49 (currency), 55 (EMV data, binary), 90 (original data elements, for reversals)
- `Iso8583Message` with indexer access, `TryGetField`, immutable after build
- A `ToString()` that renders a **field-by-field trace with PAN masked** — you will
  live in this output for weeks, make it good

### Framing and transport
- 2-byte big-endian length prefix, then message body
- Async socket server using `Socket` + `Pipe` or `NetworkStream` + `PipeReader`. Handle
  partial reads and coalesced messages correctly — write a test that feeds the parser
  one byte at a time and another that feeds three messages in a single buffer.

### Host simulator
Configurable rule engine, driven by a JSON config:
- Approve below a threshold, decline above it
- Decline specific test PANs with specific response codes (51 insufficient funds,
  05 do not honour, 54 expired card)
- Injectable latency and forced no-response (to exercise terminal timeouts)
- Duplicate detection on STAN + terminal id
- Message types: `0100/0110` authorisation, `0200/0210` financial,
  `0400/0410` reversal, `0800/0810` network management (echo test, sign-on)
- Maintains an in-memory ledger so reversals can be verified as actually reversing

## Tests
- **Property-based round trip:** random valid messages encode then decode to equality
- Byte-exact golden-file tests for at least six hand-constructed messages, with the
  expected hex committed and human-annotated
- Bitmap edge cases: field 1 only, field 128 present, no secondary bitmap
- Framing tests: byte-at-a-time, coalesced, oversized-length rejection, truncated
- Malformed input must produce a diagnostic error, never an unhandled exception

## Demo — `scripts/demo-01.ps1`
Start the host simulator, send an approval, a decline, a timeout and a reversal from a
test client, and print the decoded field-by-field trace of every message in both
directions.
